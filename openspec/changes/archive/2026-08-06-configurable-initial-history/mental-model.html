Additive; no schema migration. Follows the sync-rate-limit settings pattern.

The mental model

Transactions are pulled only through Plaid's cursor-based /transactions/sync — there is no date window in this codebase at all. Two distinct things decide "how far back":

  • Depth is set once, at link time. transactions.days_requested on /link/token/create fixes how much history Plaid will ever make available for that item. It was never set, so every item got Plaid's 90-day floor.
  • Position is the cursor. A fresh item has cursor = NULL, so the first sync streams everything available; afterwards the stored cursor yields only the incremental delta. Ongoing sync has no window to configure and is untouched by this change.

What changed

  • New admin setting. One row in the existing settings table under a new INITIAL_HISTORY_DAYS_KEY, validated to 90–730 (Plaid's supported range), defaulting to 90 when unset or invalid.
  • New card on /settings. A number input modeled on the sync rate-limit card, admin-gated (members 403), with en/es labels and help text.
  • Wired into the Plaid layer. createLinkToken() reads the setting, parses with a defensive fallback, and adds transactions: { days_requested: N } to the request.
  • New links only. The value binds at link time. Raising it later does not backfill already-linked items, does not touch cursors, and does not change ongoing syncs.

Cost note (researched, not assumed)

  • No documented depth surcharge for Transactions. Plaid bills the Transactions product as a per-Item subscription; neither the Transactions docs nor the Link API reference tie a fee to days_requested. The only documented consequence of a larger window is that "the historical update poll will take longer".
  • Don't confuse this with the Assets fee. Plaid's billing page documents a flat per-Item "Additional History" fee above 61 days — that is under Assets, a different product. This project sets PLAID_PRODUCTS=transactions, so it does not apply.
  • Still contract-specific. Plaid does not publish Transactions rates; a negotiated or legacy plan could differ. Hence the help text points operators at their own Plaid Dashboard instead of naming a number, and the default stays at 90 so no one opts into cost by accident.
